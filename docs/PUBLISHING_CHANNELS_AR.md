# قنوات النشر الرسمية

هذا الملف يوضح الفرق بين المستودعات الرسمية ومتاجر التطبيقات، وما هو جاهز
فعليًا، وما يحتاج إلى حساب أو مراجعة بشرية. لا تُعتبر أي قناة منشورة حتى
تقبلها الجهة المسؤولة رسميًا.

## الحالة الحالية

| القناة | النوع | الحالة | ما يلزم |
|---|---|---|---|
| GitHub Releases | إصدار مباشر | منشور `v1.0.8` | لا شيء |
| AppImageHub | كتالوج تطبيقات | منشور | لا شيء |
| مستودع APT/RPM على GitHub Pages | مستودع طرف ثالث موقّع | يعمل | لا شيء |
| AUR | مستودع مجتمعي | الملفات جاهزة، غير منشورة | حساب AUR وتسجيل مفتاح SSH |
| Debian الرسمي | مستودع توزيعة | تغليف `debian/` جاهز تقنيًا | حساب Debian Mentors وراعٍ |
| Fedora الرسمي | مستودع توزيعة | `packaging/fedora/` جاهز تقنيًا | حساب FAS وطلب مراجعة |
| Snap Store | متجر تطبيقات | لم يبدأ | حساب Snapcraft ومراجعة يدوية |
| Flathub | متجر تطبيقات | غير مناسب حاليًا | إعادة تصميم العزل وسياسة Flathub |

## المرحلة 1: Debian وFedora

تمت إضافة تغليف يستخدم حزم النظام بدل تشغيل Python وPySide6 المضمّنين:

- `debian/` لحزمة Debian/Ubuntu.
- `packaging/fedora/network-monitor.spec` لحزمة Fedora.
- علامة `/usr/share/network-monitor/distro-managed` تمنع المحدّث الداخلي من
  استبدال حزمة التوزيعة بحزمة GitHub.
- سير عمل `.github/workflows/distro-packages.yml` يبني الحزمتين داخل حاويات
  Debian وFedora.

بعد دفع التغييرات إلى GitHub، شغّل سير العمل `distro-packages` وتأكد من نجاح
البناء والتحقق من AppStream وملف سطح المكتب.

### المطلوب منك

1. إنشاء حساب على <https://salsa.debian.org> وحساب على
   <https://mentors.debian.net>.
2. بناء حزمة مصدر موقّعة ورفعها إلى Debian Mentors، أو طلب راعٍ Debian.
3. إنشاء حساب Fedora على <https://accounts.fedoraproject.org> ثم فتح
   `Review Request` في Bugzilla بعد بناء `src.rpm`.

هذه القنوات هي الأقرب لتظهر داخل GNOME Software وKDE Discover وUbuntu App
Center لأنها تقرأ مستودعات التوزيعة الرسمية.

## المرحلة 2: Snap Store

الحزمة الكاملة تحتاج وصولًا إلى `/proc` وcgroup v2 وnftables. لذلك الخيار
الأقرب هو `confinement: classic`، لكنه يحتاج مراجعة يدوية من Snap Store.

قبل النشر يجب حلّ إحدى النقطتين:

- تشغيل مساعد الحظر كخدمة snap تعمل بصلاحيات root وتتواصل مع الواجهة عبر
  مقبس محلي، أو
- نشر نسخة مراقبة فقط دون حظر، وتوثيق ذلك بوضوح.

المطلوب: حساب Snapcraft، حجز الاسم `network-monitor`، وبناء الحزمة بـ
`snapcraft` ثم رفعها للمراجعة.

## المرحلة 3: Flathub

Flathub أكبر متجر تطبيقات لينكس، لكنه لا يناسب البنية الحالية مباشرة:

- Flatpak يعزل العمليات، فلا تستطيع الواجهة رؤية تطبيقات النظام الأخرى عبر
  `/proc` بالشكل المطلوب للمراقبة لكل تطبيق.
- الحظر عبر cgroup v2 وnftables يحتاج مساعدًا على المضيف، وهو خارج نموذج
  العزل المعتاد.
- سياسة Flathub تمنع صراحةً أن يفتح وكيل ذكاء اصطناعي طلب النشر أو يولّد
  ملف الـmanifest أو رسائل المراجعة.

لذلك يجب أن ينشئ المستخدم ملف Flatpak ويفتح طلب النشر بنفسه، أو نكتفي بنسخة
مراقبة محدودة الوظائف بعد قرار منفصل.
